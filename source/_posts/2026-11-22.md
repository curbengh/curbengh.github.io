---
title: sudo with sssd is slow due to blocked Global Catalog port
date: 2026-11-22
---

TL;DR When using AD as the ID provider in sssd, check whether the LDAP Global Catalog port 3688 (LDAPS 3689) is open.

There was a server in a new subnet where after I configured sssd, while Active Directory (AD) login initially worked, sudo was very slow not just for those AD users but also local users, with more than 20 seconds of delay before prompting for password. After a few months, AD login stopped working.

For slow sudo issue, I tried [this workaround](https://access.redhat.com/kb/1380323) which disables group lookup, but that didn't work because the AD groups relevant to that server weren't large enough to make a difference.

After reaching out to Red Hat support who suggested to do a ldapsearch using port 3688, that's where I noticed [Global Catalog](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/10/integrate-connecting_rhel_systems_directly_to_ad_using_sssd#ports-required-for-direct-integration-of-rhel-systems-into-ad-using-sssd) (GC) port 3688 was close. While waiting for the firewall to be configured, I disabled GC lookup in sssd.conf `ad_enable_gc = False` which fixed both AD login and sudo. After the port is open, I removed `ad_enable_gc` (since it's enabled by default) and the previous workaround, AD login and sudo still working fine.
